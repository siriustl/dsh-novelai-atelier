Applies to `nai-diffusion-5-full` and `nai-diffusion-5-curated`. Public prompting documentation was rechecked on 2026-10-02; see [sources.md](sources.md). Practical starting values and authored examples are guidance, not API guarantees.

## Choose Full or Curated deliberately

| Property | V5 Full | V5 Curated |
|---|---|---|
| Training coverage | Broader, less filtered dataset; useful for specific concepts | Smaller, cleaner, more focused dataset |
| Base prompt budget in model docs | About 1,471 effective tokens | About 703 effective tokens |
| Lettering budget in text-rendering docs | Up to 750 characters including spaces/newlines | Up to 374 characters including spaces/newlines |
| Separate character prompts | Up to 22 | Up to 22 |
| Natural language | Improved multilingual understanding | Improved multilingual understanding |
| True alpha generation | Supported | Supported |
| Image-to-image / Enhance | Advertised in current capabilities | Advertised in current capabilities |
| Inpaint | Endpoint verified | Endpoint unavailable in 2026-09-20 live test; choose another model explicitly |
| Vibe / Precise Reference | Not supported by current model capabilities | Not supported by current model capabilities |
| Free Opus generation | Rechargeable usage allowance required | Rechargeable usage allowance required |

Full is a useful general default when flexibility matters. Curated is worth choosing for a cleaner/focused model or when the user asks for it. A Full-to-Curated switch changes the model, rather than acting as an extra quality setting. Preserve the user's choice and do not silently substitute.

Do not pad a prompt to its token limit. The published V5 base limits do not establish an unlimited character-prompt budget. Keep each character description focused and use the server/model tokenizer when exact capacity matters. The model overview calls the text limits "tokens" while the dedicated text guide calls them "characters"; follow the latter conservatively for lettering.

## Choose a form that fits the scene

NovelAI is an anime/illustration model by default. Use character design, expression, costume, linework, shading and composition appropriate to that domain. Do not add photography, aging skin, anatomical microdetail or `background dataset` merely to make a prompt sound more sophisticated.

Tags, prose and mixtures are all supported. These are alternative forms, not a required three-step expansion:

**Tag-led character illustration (authored starting point):**

```text
1boy, solo, white hair, blue eyes, armor, red cape, holding sword, looking at viewer, outdoors, castle, wind
```

**Natural-language alternative:**

```text
An anime illustration of a white-haired knight in armor standing before a castle, his sword lowered. His red cape blows to the left.
```

**A short mixed prompt when direction matters:**

```text
1boy, solo, white hair, blue eyes, armor, red cape, holding sword, outdoors, castle. His sword points down, and his cape blows to the left.
```

The first relies on familiar tag vocabulary. The sentences in the other two are ordinary descriptions, not asserted Danbooru tags. Do not mechanically append prose to a tag prompt that already expresses the brief; conversely, do not break clear user-written prose into tags merely because it is prose. The same choices apply to anime scenery or illustrated objects, such as `scenery, no humans, forest, path, sunlight, visual novel bg` with an optional sentence explaining a fork in the path.

Official V5 examples include brief tag prompts, hybrid character actions (Q0120), and long natural-language illustration descriptions (announcement B12). They demonstrate viable forms, not a universal winner. Our examples here are adaptations, not copies of those images' complete prompts.

A local comparison of these three forms for a library character used two seeds on both V5 models. All conveyed the broad character/book scene; prose variants tended toward more detailed shading and different viewpoints, while hand arrangements still varied. The authored phrasings were not perfectly semantically identical, so this is evidence to inspect style and ownership after a rewrite, not proof that one syntax is inherently better.

## Documented V5 custom controls and alpha features

The official tagging page names these controls. Some are NovelAI-specific tags; alpha-related words also have ordinary/tag meanings elsewhere. Their documented V5 functionality is the relevant distinction, not whether the words appear in another tag database:

| Tag | When it helps |
|---|---|
| `attractive male` | A V5-specific cue for an appealing male appearance; combine with actual face/body design |
| `depthness` | Push shading toward greater depth; use only if dimensional shading fits the medium |
| `low complexity`, `medium complexity`, `high complexity`, `ultra complexity` | Select the density/character of the image, not a monotonic quality score |
| `meta:novel era`, `meta:golden era` | Subtle less-modern / slightly-more-modern biases, respectively |
| `visual novel art`, `visual novel bg`, `visual novel cg`, `visual novel chibi`, `visual novel sprite` | Explore those visual novel presentation styles |
| `transparent background` | Ask for a transparent background |
| `has alpha` | Ask to use the alpha channel in some way |
| `alpha transparency` | Ask for translucent scene elements, such as magic or glass-like effects |

The official recommendation for a normal detailed image is often `high complexity`; `ultra complexity` is not automatically better. Low and ultra can both lead to pronounced stylization. For a clean avatar or sprite, test lower complexity instead of forcing detail everywhere.

Use only the alpha cue needed for the task. `transparent background` has a narrower intention than `has alpha`. If a background persists, the docs suggest strengthening it, such as `2.1::transparent background::`; first remove landscape/location/background instructions that contradict the cutout. Check actual alpha values in the PNG rather than assuming a checkerboard-looking image is transparent. Do not put an alpha-removing conversion into the export pipeline.

The plugin exposes the website checkbox as `transparent_background: true`. It adds the plain `transparent background` tag before the quality suffix (and before any lettering), plus the official API hint. It works with `quality_preset: "none"`; this is independent of `straight_alpha`. In four paired local tests, manually adding the same tag versus using the checkbox produced identical RGB pixels. The control reproduces the website workflow; it is not an extra image-quality or transparency-strength boost. Keep it false when intentionally writing a custom weighted transparency phrase yourself.

Use `nai_image_info({action:"inspect",path:...})`'s `alpha` statistics to verify real transparency. The tool groups alpha 254 with 255 so hidden metadata bits are not mistaken for a transparent background. Four local V5 samples had substantial transparent pixels but also added unrequested ice/sword effects; alpha support does not guarantee a clean isolated silhouette or adherence to every prop request.

## Tags plus natural language

V5 understands multilingual prompts and can render English, Japanese, Chinese, and other languages. The official V5 page names English/Japanese as primary supported prompt languages, with usable Chinese/German/Spanish/Portuguese test results that can be less consistent. For portable examples, English lowercase tags remain clear, while prose can use the user's preferred language. A translated tag suggestion is not evidence that the literal foreign tag is a canonical tag. Use known tags for taxonomy and normal prose for things that do not fit a tag.

Use canonical spellings for known tags when available, and natural sentences for descriptions that are not standardized tags. For example:

```text
2boys, library, table, book. The boy with white hair points at the open book; the boy with black hair looks at the same page.
```

The count/setting words are tag-style anchors, and the final sentence binds the action. This is an illustration example, not a requirement to prescribe every finger or facial plane. A canonical tag is not automatically the right choice: `mature male` suggests a middle-aged or older look, and `bishounen` is a particular beauty/style cue. Neither is a routine replacement for `adult man`. No age phrase is a mandatory suffix for `1boy`.

## Multi-character scenes

Use a base prompt for subject count, shared environment, framing, medium, and the interaction. Put identity and costume in individual character prompts. The newer multi-character guide explicitly recommends `boy` rather than `1boy` in the character prompt, even though older examples elsewhere contain the latter.

```text
Base:
2boys, side-by-side, upper body, train station, evening, warm backlighting. Two men greet each other. The dark-haired man on the left puts an arm around the shoulders of the silver-haired man on the right; both smile.

Character 1:
boy, short black hair, brown eyes, tan skin, navy coat, source#hug

Character 2:
boy, silver hair, blue eyes, pale skin, green scarf, target#hug
```

Give each a distinct silhouette and color story. Keep left-to-right list order and explicit positions consistent. V5 has more flexible positioning than V4.5's 5×5 grid, but exact coordinates must follow the available tool schema; they are a guide, not a guarantee of every limb position.

`source#hug`, `target#hug`, and `mutual#hug` are documented action syntax. Reliability is imperfect. Use a short sentence to reinforce who is acting on whom, and use character-specific UC to combat attribute leakage if it appears. Do not put each person's hair color in the base prompt and expect clean assignment.

For an exchange or shared prop, identify its current owner, which hands contact it, and whether the transfer has finished. Use a short existing appearance cue to disambiguate the participants when useful; do not repeat their entire descriptions. This applies equally to any genders and to people interacting with an object. Character coordinates describe placement; they are not a documented depth channel or a guarantee of contact geometry.

Twenty-two characters is a capacity, not a recommended target for a first attempt. Crowded scenes divide the available pixels and increase ambiguity. Begin with the few characters the brief actually needs.

For framing, compare canvas shape as well as words. In a two-character local trial, square canvases exposed more upper legs than landscape at the tested seeds, yet hair tips were still cropped and fist contact remained imperfect. Likewise, adding `wide shot` to a full-body outfit sometimes introduced an elaborate background. These are options to test, not automatic repairs or new required tags.

If an interaction degenerates into two people posing beside each other, reconsider their body orientation and the space the action needs. In follow-up fist-bump examples, a full-body frame and prose describing horizontally extended arms/front-knuckle contact gave more readable poses. That revision changed multiple choices; it does not prove that longer prose, automatic positioning or full-body framing is always best. The tested request is in [examples.md](examples.md).

## Quality, negative content, and artistic intent

Official quality suffixes are the same for V5 Full and Curated:

- Light: `very aesthetic, amazing quality, no text`
- Standard: `very aesthetic, masterpiece, no text`

They are suffixes added to the positive prompt, not hidden model capabilities. If the plugin applies them, do not duplicate them manually. Their aesthetic bias may affect sketch, manga or restrained graphic styles. If the actual result drifts from the intended style, compare a lighter or disabled quality template while holding other settings fixed; do not turn it off automatically for every illustration.

Official Light UC:

```text
lowres, bad hands, bad anatomy, artistic error, sepia, white haze, worst quality, very displeasing, jpeg artifacts, 0::ai-generated::
```

Official Heavy UC:

```text
lowres, artistic error, film grain, scan artifacts, worst quality, bad quality, jpeg artifacts, very displeasing, chromatic aberration, dithering, halftone, screentone, multiple views, logo, too many watermarks, negative space, blank page
```

Use a small custom UC if a preset opposes the requested result. Examples: Heavy contains halftone and dithering exclusions; Light contains sepia. These are possible conflicts to inspect, not guarantees that the style will disappear. Do not call an image objectively "better" solely because Heavy removes intentional texture.

`-1::hat::` in the positive prompt is a targeted negative weight; `hat` in UC is a general exclusion. They are related steering tools, not interchangeable arithmetic. Strong negatives can distort neighboring concepts. Start with a modest change and inspect the result.

## Lettering and panels

Describe the scene and text placement before the final `Text:` section. Put every desired text block at the end of the base prompt, separated by an empty line. `Text:` must be last, otherwise trailing tags may appear in the image. Avoid an automatic `no text` suffix and UC terms such as `text`, `logo`, or `multiple views` when those are intentionally needed.

```text
1boy, solo, attractive male, upper body, short black hair, blue jacket, railway platform, poster, text, chinese text. An illustrated travel poster showing a man holding a train ticket. The two large Chinese characters appear at the top with ample clear space around them. Restrained blue and cream palette.
Text: 出发
```

Prefer the server's separate `text` field when it supports one; then leave `Text:` out of `prompt`, and let the compiler append it safely. Do not supply both forms.

Manual delimiters also follow the website's case/boundary rules (`text:` / `teXt:` are recognized); compiled output normalizes the final marker to `Text:`. A delimiter inside an unrelated word is not recognized. A local eight-image test spelled short Chinese/English targets correctly, but unplaced text appeared on shirt labels or straps. Name the sign, screen or other carrier when placement matters; correct spelling alone does not establish correct layout.

V5 can handle fully paneled comics, but prompt each panel's action clearly and avoid changing a character's identity between panels. A simple two-panel scene with short lettering is a more informative first test than filling the maximum text budget. Inspect actual spelling and text placement; generation success alone is not textual accuracy.

Keep a small continuity record for a sequence: identities and object designs are stable facts, while held objects, open/closed parts, and contact change over time. Describe only what the current shot shows, without forgetting facts outside the crop. A close-up does not make a previously held object disappear when the wider shot returns. Specify the actual text carrier—sign, screen, label, speech bubble—and its relation to the subject. Complex community workflows that reuse character slots as panel containers remain experiments, not a separate official per-panel API.

## Dataset switching

Use `fur dataset` at the very start when deliberately selecting the furry dataset. Do not add it merely because an anime human character has animal ears. Use anatomy/species appropriate to that request rather than importing every human face/body cue.

`background dataset` also belongs at the very start, but the official docs describe it for landscapes, animals, still lifes, and other **images without people** in a photographic style. It is not a general photorealistic-men switch. Do not add it by default to anime scenery, game backgrounds, character art or props; use it only when the user actually requests the supported photographic direction.
